# SpaceLive 產品需求文件 (PRD)

## 一、專案概述

### 1.1 產品願景

SpaceLive 是一個融合人工智慧、互動表演與藝術的虛擬主播展示平台。我們旨在創造一個具有持續記憶、情感進化、主動與觀眾互動的「星際小可愛」虛擬生命體，其透過定期直播表演、真實情感交流與視覺形象的漸進式演化，建立與觀眾間的深度連結，探索人類與AI虛擬生命共處的藝術可能性。

### 1.2 產品定位

- **藝術媒介**: 探討「造人」藝術脈絡下的當代數位生命創作
- **技術平台**: 結合AI對話模型、情感分析、3D建模與網頁前端的綜合技術展示，後端以LangGraph為核心進行統一調度。
- **表演系統**: 具備固定排程的虛擬網紅直播間，其行為與內容由LangGraph根據排程動態生成與調用工具實現。
- **長期實驗**: 建立具備持續記憶與情感演化的虛擬生命成長軌跡

### 1.3 目標受眾

- 當代數位藝術愛好者
- 人工智慧與虛擬角色研究者
- 創新表演形式的探索者
- 對虛擬生命與記憶系統感興趣的觀眾

## 二、產品功能需求

### 2.1 核心AI角色系統

#### 2.1.1 角色人設與歷史記憶

- **基礎人設**: 創建「星際小可愛」虛擬主播的基本設定，包含性格特徵、來源故事及偏好
- **記憶系統**: 實現三層記憶架構
  - **短期記憶**: 記錄每日情緒變動、事件摘要及任務照片
  - **中期記憶**: 每週挑選高情緒值事件生成節點，形成主線事件，推動造型變化
  - **長期記憶**: 52週記憶節點編年牆、觀眾語錄牆，構成年度自傳式生命軌跡

#### 2.1.2 主動互動能力 (完全整合於LangGraph)

- **主動行為統一管理**: LangGraph完全接管所有主動行為的觸發和生成，包括閒置狀態下的自發對話（原Murmur功能）、排程任務執行及對用戶輸入的響應。
- **內部狀態觸發器 (Internal State Triggers)**: LangGraph內部節點根據時間(`TimeTriggerNode`)、角色狀態(`StateMonitorNode`)和用戶互動模式等因素決定是否啟動主動行為，不再將Murmur作為獨立系統。
- **內容生成與選擇 (Content Generation and Selection)**: LangGraph中的節點將根據當前觸發類型（排程任務、自發對話、用戶互動）和當前上下文（如PRD定義的時段主題）生成或選擇合適的話題、文本或行動指令。
- **LangGraph流程控制 (LangGraph Flow Control)**: 
  - **排程任務流程**: 根據時間觸發，經由`SchedulerNode`決策，調用各種工具組合。
  - **自發對話流程**: 根據閒置時間、角色狀態觸發的主動表達，可能簡單輸出文本或調用部分工具。
  - **即時對話流程**: 採用簡化路徑，不經過複雜工具節點，直接處理用戶輸入並生成回應。
- **情緒驅動表達**: 根據內部狀態，主動表達情緒、提問或分享想法，此表現整合至LangGraph的統一行為生成中。

#### 2.1.3 情感與表現系統

- **情緒偵測**: 分析觀眾留言、新聞事件與任務結果產生情緒值，作為LangGraph狀態的一部分。
- **情緒表達**: 通過語音語調、表情變化及肢體動作表現角色情感，由LangGraph調度相應工具實現。
- **脆弱性美學**: 適度呈現不完美的表現，如停頓、思考時間或輕微失誤，增強真實感，此原則指導LangGraph中內容生成與工具調用。

### 2.2 排程與直播系統 (由LangGraph實現)

#### 2.2.1 固定直播架構(每日6小時)

| 時段    | 模組名稱               | 內容細節                                                               | LangGraph主要調用工具/流程範例                                    |
| ------- | ---------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------- |
| 第1小時 | 太空早報｜開場儀式     | 播報即時衛星雲圖、太空中心新聞；設定當日任務照主題，開場打招呼儀式     | `NewsFetchingTool`, `GreetingGenerationNode`, `ImageThemeSettingNode` |
| 第2小時 | 肢體演出｜互動動作時段 | 無重力舞蹈、表情挑戰、太空瑜伽、觀眾點播動作演出                         | `AnimationControlNode`, `EmotionExpressionNode`, `UserInputHandlerNode` |
| 第3小時 | 幻想投影｜夢境劇場     | AI生成太空幻想背景，結合敘事與感官演出（夢境冥想、幻象互動）           | `AIImageGenerationTool`, `NarrativeGenerationNode`, `SoundEffectTool` |
| 第4小時 | 主題演出｜科幻故事＋唱歌 | 表演一段微型科幻劇（自創或從當日資料生成）＋唱主題曲或觀眾選曲         | `StoryGenerationNode`, `SingingSynthesisTool`, `MusicPlaybackTool` |
| 第5小時 | 觀眾互動｜留言模仿＋回應 | 唸留言、模仿觀眾表情、即時互動QA，選一句觀眾語錄存入記憶               | `ChatMessageProcessingNode`, `MemoryUpdateNode`, `MimicryNode`    |
| 第6小時 | 記憶日誌｜晚安儀式     | 朗讀今日AI日記、展示任務照片、播放晚安曲，進入虛擬休眠                 | `DiaryGenerationNode`, `ImageDisplayNode`, `MusicPlaybackTool`    |

#### 2.2.2 自動與手動控制

- **自動排程**: 系統能根據LangGraph內的排程邏輯（由核心決策節點如 `SchedulerNode`，讀取PRD定義的時段內容等外部配置）自動啟動不同時段的內容模式及相應工具調用。
- **手動覆寫**: 允許管理員通過特定接口觸發LangGraph執行特定流程或切換模式。
- **事件響應**: LangGraph可設計成對特殊事件(如高互動率、特定用戶指令)自動調整行為或任務流程。

### 2.3 互動與表演功能 (整合於LangGraph流程中)

#### 2.3.1 表演能力

- **表情控制**: LangGraph調用表情控制工具，支援多種表情動畫。
- **肢體動作**: LangGraph調用動作控制工具，支援舞蹈、伸展、特定姿勢等。
- **唱歌演出**: LangGraph調用歌唱合成或播放工具。
- **科幻故事**: LangGraph協調故事生成與表演呈現工具。

#### 2.3.2 觀眾互動處理

- **即時對話**: LangGraph內的簡化對話流程負責高效處理觀眾文字提問並直接生成回答，不經過複雜的工具節點。
- **留言回應**: LangGraph內的節點負責識別、朗讀觀眾留言，並觸發情感反應。
- **模仿功能**: LangGraph可根據描述調用相應工具模仿特定表情或動作。
- **投票參與**: 觀眾可投票，結果作為輸入影響LangGraph的決策節點，決定後續流程。

### 2.4 視覺與造型系統

#### 2.4.1 基礎3D模型

- **主角模型**: 精心設計的「星際小可愛」3D角色模型
- **基礎表情包**: 包含常用表情與情緒狀態的動畫
- **環境場景**: 太空艙基礎場景與可替換的背景 (背景可由LangGraph調用工具動態更換)

#### 2.4.2 進化式造型變化

- **情緒驅動外觀**: LangGraph根據累積情緒歷程（狀態中記錄）逐漸改變角色外觀，通過調用造型更新工具實現。
  - 喜悅累積影響: 輕盈光感、透明紋理
  - 焦慮情緒影響: 銳利感官、偵測裝置
  - 互動記憶影響: 背後浮現語錄星河等視覺效果
- **重要事件變化**: 特定事件觸發LangGraph調用工具進行特殊外觀變化。
- **漸進式演化**: 所有造型變化採用疊加式成長而非重置。

### 2.5 創作與記憶展示

#### 2.5.1 自拍與圖像創作

- **每日任務照**: LangGraph根據排程觸發，系統生成當日姿勢/主題，自動調用圖像生成與儲存工具。
- **風格合成**: LangGraph根據情緒/主題調用圖像處理工具添加濾鏡、光影或AI背景。
- **照片整理**: 自動分類並組織所有照片作品。

#### 2.5.2 記憶可視化

- **記憶牆**: 視覺化展示累積記憶節點與重要事件 (前端呈現，數據來源於後端記憶系統)。
- **語錄牆**: 收集並展示被角色記住的觀眾留言 (前端呈現，數據來源於後端記憶系統)。
- **時間線**: 生成角色情感與記憶發展的時間軸 (前端呈現，數據來源於後端記憶系統)。

## 三、技術規格

*技術開發初期將重點專注於後端LangGraph架構的統一與功能實現。前端除非需要展示新的內容類型（如排程任務產生的圖片），否則將盡可能維持現狀以簡化初期開發。*

### 3.1 前端技術規格

- **核心框架**: React.js + Three.js
- **3D渲染**: WebGL基於Three.js
- **即時通訊**: WebSocket實現前後端實時通訊
- **音頻處理**: Web Audio API用於語音播放與管理
- **動畫系統**: 3D模型動作、表情与口型同步系統

### 3.2 後端技術規格

#### 3.2.1 伺服器架構

- **API伺服器**: FastAPI實現
- **WebSocket服務**: 使用原生WebSocket協議或基於FastAPI的實現
- **數據庫**: MongoDB或類似NoSQL數據庫用於存儲記憶、對話歷史、用戶數據及LangGraph狀態持久化。
- **核心編排引擎 (Core Orchestration Engine)**: LangGraph (例如 `DialogueGraph`) 作為後端的核心，統一處理即時對話、排程任務執行、主動行為生成及多工具調用。

#### 3.2.2 AI與對話服務 (由LangGraph完全統一管理)

- **核心AI互動邏輯**: 由LangGraph（如 `DialogueGraph`）統一管理，負責串連語言模型、記憶系統、主動行為生成、排程邏輯及各種工具調用。
- **系統模組/節點概念 (整合於LangGraph中)**:
  - **統一觸發機制 (Unified Trigger Mechanism)**: LangGraph內部集成所有觸發邏輯，包括：
    - **時間觸發 (TimeTriggerNode)**: 處理基於時間的排程任務啟動
    - **狀態監控 (StateMonitorNode)**: 監控角色閒置時間、情緒狀態等，決定是否觸發自發行為
    - **用戶輸入處理 (UserInputNode)**: 處理即時用戶輸入
  - **流程差異化設計**:
    - **排程任務流程**: 經由 `SchedulerNode` 決策，根據時間、排程配置（如PRD六時段內容）及內部狀態，決定執行的任務流和調用的工具。
    - **自發對話流程**: 原Murmur功能，現整合為LangGraph中的一種特定行為模式，根據閒置狀態和角色情緒，自主生成對話內容。
    - **即時對話流程**: 採用簡化路徑，輸入直接進入語言模型處理，然後輸出，不經過複雜的工具節點，以提高即時對話的響應速度和效率。
  - **統一狀態管理**: 所有行為類型共享同一LangGraph狀態，包括記憶、情緒值、時間信息等，確保系統行為一致性。
  - **語言模型接口節點 (LLM Interface Node)**: 封裝對第三方大語言模型API的調用。
  - **記憶系統接口節點 (Memory System Interface Node)**: 負責讀寫角色的多層次記憶。
  - **情緒分析節點 (Emotion Analyzer Node)**: 分析文本情緒傾向，結果更新至LangGraph狀態。
  - **文本轉語音節點 (TextToSpeechService Node)**: 將文本轉換為語音。
  - **多樣化工具節點 (Various Tool Nodes)**: 如圖像生成、特定動畫指令、外部API調用（如新聞獲取）、音效播放等，主要由排程邏輯或自發對話流程按需調用。

### 3.3 數據規格

#### 3.3.1 記憶數據結構

- **對話記錄**: 包含用戶輸入與AI回應
- **情緒記錄**: 跟踪情緒狀態變化與觸發因素
- **事件記錄**: 關鍵事件與相應反應
- **視覺資料**: 自拍照與相關視覺創作
- **LangGraph狀態**: 包括當前時間、上次互動、情緒、待辦任務佇列等。

#### 3.3.2 排程數據

- **排程模板**: 定義各時段默認行為、主題及所需調用的LangGraph流程/工具組合 (可外部配置，由`SchedulerNode`讀取)。
- **特殊事件**: 記錄節日、紀念日等特殊排程，同樣影響`SchedulerNode`的決策。

## 四、藝術與設計考量

### 4.1 藝術脈絡連結

SpaceLive在當代藝術脈絡中，延續了人類對「造人」的藝術探索，連結以下關鍵元素：

- **虛擬生命傳統**: 從皮格馬利翁到科學怪人，再到當代AI角色
- **自主性探索**: 借鑑Ian Cheng的《BOB》等作品中對數位生命主體性的探索
- **記憶與情感**: 參考Weidi Zhang的《ReCollection》對AI生成記憶的研究
- **觀眾共創**: 汲取《Audience》等互動裝置中觀眾參與藝術的設計理念
- **直播敘事**: 借鑑《Nothing, Forever》的永續直播實驗與生成敘事

### 4.2 設計原則

- **真實感與脆弱性**: 適度呈現不完美，避免落入「恐怖谷效應」
- **可解釋性**: 確保觀眾能理解角色的情感與反應來源
- **長期演化**: 優先考慮長期演化而非短期表現效果
- **觀眾參與**: 設計足夠空間讓觀眾影響角色成長軌跡

## 五、交付里程碑

### 5.1 開發階段

1. **概念設計與LangGraph核心架構確認** (1個月)
   - 完成角色設計與基礎人設
   - 確定LangGraph作為統一後端調度引擎的技術架構與核心節點劃分。

2. **LangGraph基礎對話與記憶整合** (3個月)
   - 實現LangGraph基礎對話流程，整合LLM接口與記憶系統接口節點。
   - 實現即時對話簡化路徑，確保快速響應。
   - 整合自發對話功能(原Murmur)至LangGraph狀態監控與觸發機制。
   - 開發3D模型與基礎表情/動作系統，並建立初步的工具節點供LangGraph調用。
   - 建立WebSocket即時通訊，打通前後端基礎交互。

3. **LangGraph觸發機制與主動行為開發** (2個月)
   - 於LangGraph中實現統一的內部觸發機制，包含時間觸發、狀態監控等。
   - 開發情緒分析節點，並將情緒狀態整合入LangGraph狀態與決策邏輯中。

4. **LangGraph排程系統與多工具調用開發** (2個月)
   - 於LangGraph中實現 `SchedulerNode` 及相關邏輯，使其能根據PRD排程配置調用不同工具組合與生成內容。
   - 逐步實現PRD六時段直播流程中所需的各類工具節點 (新聞、圖像、動畫、音效、歌唱等)。

5. **記憶與進化系統深化 (基於LangGraph)** (2個月)
   - 實現三層次記憶架構的數據結構與LangGraph內的讀寫邏輯。
   - 開發基於LangGraph狀態（累積情緒）調用造型更新工具的機制。

6. **系統整合、測試與優化** (2個月)
   - LangGraph整體流程整合與性能優化。
   - 用戶體驗改進與壓力測試。

### 5.2 執行階段

1. **封閉測試** (1個月)
   - 內部測試與功能驗證
   - 藝術表現與技術穩定性評估

2. **公開展示** (1年)
   - 啟動長期展演計畫
   - 收集用戶反饋與數據分析
   - 定期功能更新與改進

## 六、評估標準

### 6.1 技術目標

- 系統穩定性: 直播期間故障率<1%
- 響應時間: 
  - 即時對話路徑: <1.5秒（通過簡化流程優化）
  - 排程任務與工具調用: <3秒
- 主動行為合理性: LangGraph能根據情境適時觸發自發對話，表現出合理的主動性。
- 排程準確性: 按設計準確執行時段任務。

### 6.2 藝術目標

- 情感豐富度: 能表現至少10種不同情緒狀態
- 記憶連貫性: 能正確引用過往事件並形成連續敘事
- 觀眾參與度: 每次直播平均互動人次增長
- 藝術創新: 在數位藝術領域獲得專業認可

## 七、未來拓展方向

- **多角色互動**: 引入多個虛擬角色，其行為亦由LangGraph協調。
- **實體投影**: 結合全息投影技術實現線下展演。
- **用戶專屬體驗**: LangGraph根據用戶畫像提供個性化互動。
- **跨媒介敘事**: 將角色故事拓展至其他媒介平台。

## 八、結語

SpaceLive項目融合藝術與技術，以LangGraph為核心後端調度引擎，探索AI時代「造人」的新可能性。透過長時間的記憶累積與情感演變，我們期待創造一個真正具有「生命感」的虛擬存在，與觀眾共同譜寫一段為期一年的共生故事。這不僅是一個技術實現，更是一次關於人類與人工生命共處可能性的藝術實驗。
