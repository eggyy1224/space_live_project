# 現有音效系統架構分析

根據對`docs/Soundeffect_related`資料夾文檔的研究，以下是對現有音效系統架構的分析。

## 現狀概述

目前的音效系統存在以下幾個主要問題：

1. **單一元件職責過重**：`SoundEffectPanel.tsx`是一個龐大的單一元件，集成了播放音樂、合成音效以及Freesound音效搜尋等多種功能。
2. **缺乏統一協調機制**：各種聲音來源（後端TTS語音、前端歌曲、音效）缺乏統一管理，導致播放衝突。
3. **無優先級與聲音壓制**：當角色說話時，沒有機制自動降低其他音軌的音量（Ducking），導致聲音混亂。
4. **前後端職責不清**：目前部分播放邏輯在後端處理，缺乏靈活性。

## 架構設計原則

從文檔中可以提取以下關鍵的設計原則：

1. **協調而非播放**：AudioCoordinator應專注於決策邏輯和資源調度，而不直接處理播放實現。
2. **統一入口**：所有聲音播放請求必須通過AudioCoordinator處理，確保集中式決策邏輯。
3. **優先級管理**：建立明確的優先級系統，確保重要聲音（如語音）不被次要聲音（如背景音樂）干擾。
4. **事件驅動架構**：採用事件機制實現鬆耦合設計，確保系統各部分能獨立發展。
5. **可擴展設計**：系統需要支持輕鬆添加新的聲音類型和處理邏輯。

## 核心架構組件

### 1. 音效管理層面划分

系統應該被拆分為三個主要部分：

1. **UI層**：負責用戶交互和視覺呈現
   - `SongLibraryPanel`：歌曲庫面板，負責顯示歌曲列表和播放控制
   - `SynthPanel`：合成音效面板，處理Tone.js合成器
   - `FreesoundPanel`：音效搜尋面板，整合Freesound API
   - `SoundEffectPanelLayout`：負責選項卡切換與狀態共享

2. **服務層**：負責音效管理和協調
   - `AudioCoordinator`：聲音協調中心，處理排程、優先權和Ducking
   - `IAudioPlayer`：播放器接口，定義通用方法
   - 具體播放器實現：
     - `TonePlayer`：處理Tone.js合成音效
     - `PreRecordedPlayer`：處理預錄音效
     - `TTSPlayer`：處理TTS語音播放

3. **效果處理層**：負責聲音處理和效果
   - `VoiceEffectsProcessor`：為TTS語音添加實時效果

### 2. 聲音軌道設計

系統將聲音分為不同的軌道：

1. **語音軌**：處理所有語音內容（TTS）
2. **音效軌**：處理一般音效（提示音、交互音效）
3. **環境軌**：處理環境音效（雨聲、風聲）
4. **音樂軌**：處理背景音樂

每個軌道有獨立的優先級規則、音量控制和隊列管理策略。

### 3. 優先級系統

優先級系統包含多層面：

1. **軌道間優先級**：語音軌 > 音效軌 > 環境軌 > 音樂軌
2. **軌道內優先級**：每個聲音請求可以指定軌道內的優先級
3. **處理策略**：
   - 中斷策略：高優先級直接中斷低優先級聲音
   - 排隊策略：聲音按優先級排隊依次播放
   - 並行策略：允許多聲音同時播放，調整各自音量
   - 讓步策略：降低音量但不完全中斷（Ducking）

### 4. 資源分級策略

Freesound音效資源按重要程度分為三級：

1. **Tier-0**：關鍵即時資源，本地內建或預載，不允許有延遲
2. **Tier-1**：高頻使用資源，可在空檔預取或首次使用後快取
3. **Tier-2**：低頻或大型資源，按需下載

## 前後端職責

### 前端職責
- 解析AudioTimeline JSON
- 排程各個音效/語音的實際播放
- 管理音效資源和快取
- 處理優先級和Ducking
- 播放器實現和音效處理

### 後端職責
- 基於邏輯決策生成AudioTimeline JSON
- 準備語音資源（TTS合成等）
- 提供音效資源API
- 音效資源分級和管理

## 數據格式：AudioTimeline JSON

系統使用標準化的時間軸描述JSON格式：

```json
{
  "timeline": [
    {
      "track": "sfx",
      "startTime": 0.0,
      "type": "music",
      "resource": "bgm_forest01",
      "loop": true,
      "volume": 0.8
    },
    {
      "track": "voice",
      "startTime": 3.8,
      "type": "tts",
      "resource": "line_001",
      "text": "大家好，我是虛擬主播。",
      "duration": 2.2
    }
  ]
}
```

## 結論

現有音效系統需要進行重構，將龐大的單一元件拆分為更小、更專注的組件，並引入AudioCoordinator作為中央協調器。這將提高系統的可維護性、可擴展性，並解決目前存在的各種問題。

在實現上，需要採用小步驟、反覆測試的方式推進，確保每一步都穩定可靠。整個重構將分為接口定義、協調器實現、事件總線集成、面板整合測試等多個階段。
