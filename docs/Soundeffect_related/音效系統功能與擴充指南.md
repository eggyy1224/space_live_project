# 音效系統功能與擴充指南

## 1. 系統概述

音效系統是我們太空中心對話互動體驗的重要組成部分，旨在提供類似「直播網紅」和「綜藝樂隊」的聽覺體驗，增強對話的戲劇性和趣味性。目前音效系統主要由以下部分組成：

- **後端音效節點** (`SoundEffectNode`): 分析對話內容，決定適合的音效類型 (此部分功能可能已部分過時或需與重構計畫對照)
- **後端音效服務** (`SoundEffectService`): 生成具體的音效命令 (此部分功能可能已部分過時或需與重構計畫對照)
- **前端歌曲播放** (`AudioPlayerService.ts`, `SoundEffectPanel.tsx`): 使用 HTMLAudioElement 處理歌曲播放、停止和時間同步。
- **前端合成音效** (`SoundEffectService.ts`, `useSoundEffects.ts`, `SoundEffectPanel.tsx`): 使用 Tone.js 處理合成音效 (beep, noise 等) 的生成與播放。
- **前端 Freesound 整合** (`FreesoundService.ts`, `useFreesoundAPI.ts`, `SoundEffectPanel.tsx`): 負責搜索、預覽、緩存 Freesound 音效資源。
- **前端動畫同步** (`AnimationCue` 接口, `SoundEffectPanel.tsx`): 根據歌曲的時間戳觸發身體動作 (`action`) 和表情 (`emotion`)。
- **前端音效面板** (`SoundEffectPanel.tsx`): 提供 UI 界面，整合歌曲播放、合成音效測試、Freesound 搜索和音量控制等功能 (目前組件較為龐大，待重構)。
- **前端狀態管理** (`useStore.ts`): 管理動畫、語音狀態等。
- **配置** (`soundEffectsConfig.ts`): 定義預設音效、歌曲、動畫線索等靜態數據。
- **語音服務** (`AudioService.ts`): 處理 TTS 語音的播放，目前與 `AudioPlayerService` 的歌曲播放可能存在衝突。

## 2. 音效系統工作流程

### 2.1 音效生成流程 (舊版，待更新)

1. 使用者發送訊息，AI 生成回覆
2. 對話節點處理完成後，將結果（包含 AI 回應文本）傳遞給音效節點 `SoundEffectNode`
3. 音效節點進行文本分析，提取關鍵詞和特徵，決定音效模式（如 excited, serious, question 等）和強度
4. 音效節點調用 `SoundEffectService.create_tone_sequence()` 方法，生成 Tone.js 可用的音效命令
5. 音效命令通過 WebSocket 連接發送到前端
6. 前端的 `WebSocketService` 接收到 `audio-effect` 類型的消息，轉發給 `SoundEffectService.ts`
7. 前端音效服務解析命令，使用 Web Audio API 和 Tone.js 實際播放音效

### 2.2 歌曲播放與動畫同步流程 (當前)

1. 用戶在 `SoundEffectPanel.tsx` 中點擊歌曲播放按鈕。
2. `handlePlaySong` 函數被調用。
3. 設置 `isSpeaking` 狀態為 `true` (通過 `useStore`)。
4. `AudioPlayerService.playAudio(song.url)` 被調用，使用 `HTMLAudioElement` 開始播放歌曲。
5. 如果歌曲包含 `animationCues`：
    - 調用 `startAnimationLoop` 函數。
    - `startAnimationLoop` 使用 `requestAnimationFrame` 定期調用 `audioPlayerService.getCurrentTime()` 獲取當前播放時間。
    - 根據播放時間匹配 `animationCues` 中的 `time`。
    - 當時間匹配時，根據 `cue.type`：
        - 如果是 `emotion`，調用 `headService.applyPresetExpression(cue.value)`。
        - 如果是 `action`，調用 `useStore.getState().setCurrentAnimation(cue.value)`。
6. 歌曲播放結束時 (`audioPlayerService` 觸發 `end` 事件)：
    - `handleSongEnd` 函數被調用。
    - 設置 `playingSongId` 為 `null`。
    - 設置 `isSpeaking` 狀態為 `false`。
    - 調用 `stopAnimationLoop` 停止動畫循環並重置狀態。

### 2.3 TTS 播放流程 (可能衝突點)

1. 後端生成 TTS 語音和口型數據。
2. 通過 WebSocket 將語音數據 (URL 或 Blob) 和口型數據 (visemes) 推送給前端。
3. 前端 `WebSocketService` 接收消息。
4. 語音數據交由 `AudioService.ts` 處理播放 (可能也使用 `HTMLAudioElement` 或 Web Audio API)。
5. 口型數據用於驅動角色面部動畫 (`useStore.getState().setAudioLipsyncTarget`)。
6. **衝突點**: `AudioService` 播放 TTS 和 `AudioPlayerService` 播放歌曲可能會同時發生，導致聲音重疊或互相打斷，需要協調機制。

## 3. 後端音效系統詳解 (舊版，待更新)

### 3.1 SoundEffectNode (音效節點)

位置: `prototype/backend/services/ai/graph_nodes/sound_effect_node.py`

功能:
- 接收對話結果，進行非同步處理
- 分析文本以確定合適的音效特徵
- 使用正則表達式匹配關鍵詞/短語
- 計算音效強度 (intensity)，考慮感嘆號數量和文本情感
- 選擇最適合的音效模式
- 調用音效服務生成具體的音效命令

支持的模式判斷:
- `excited`: 興奮模式，上升音階
- `serious`: 嚴肅模式，下降音階
- `question`: 疑問模式，上升語調
- `thinking`: 思考模式，慢節奏
- `success`: 成功模式，歡快音效
- `important`: 重要信息模式，強調音效
- `tech`: 科技相關模式，數字化聲音
- `space`: 太空相關模式，環境聲
- `funny`: 滑稽/捧哏模式
- `fail`: 失敗模式，下滑音
- `surprise`: 驚訝模式
- `neutral`: 中性模式（預設）

### 3.2 SoundEffectService (音效服務)

位置: `prototype/backend/services/sound_effect/sound_effect_service.py`

功能:
- 提供靜態方法用於創建各種音效命令
- `create_synth_sound_command()`: 核心方法，創建合成音效命令
- `create_tone_sequence()`: 根據指定模式創建音效序列
- `create_background_music_command()`: 創建背景音樂命令
- `create_ambient_sound_effects()`: 創建環境音效
- `create_greeting_sound()`: 創建歡迎音效

音效命令格式:
```json
{
  "type": "audio-effect",
  "payload": {
    "synthMode": true,
    "effects": [
      {
        "type": "beep",
        "options": {
          "frequency": 440,
          "duration": 0.1,
          "volume": 0.5,
          "wavetype": "sine"
        },
        "startTime": 0
      },
      // 更多音效...
    ]
  }
}
```

## 4. 前端音效/音頻系統詳解 (當前)

### 4.1 `AudioPlayerService` (歌曲播放)

位置: `prototype/frontend/src/services/audioPlayer.ts`

功能:
- **核心**: 使用 `HTMLAudioElement` 實例管理音頻播放。
- 提供 `playAudio(url)`, `pause()`, `stop()`, `loadAudio(url)` 等方法。
- 提供獲取狀態的方法: `getCurrentTime()`, `getDuration()`, `isAudioPlaying()`。
- 包含基本的 Web Audio API 集成 (`AudioContext`, `AnalyserNode`) 用於音頻分析，但**不直接用於播放控制**。
- **上下文**: 主要用於 `SoundEffectPanel` 中播放歌曲，並為動畫循環提供時間基準。

### 4.2 `SoundEffectService` (合成音效與預設效果)

位置: `prototype/frontend/src/services/SoundEffectService.ts`

功能:
- **核心**: 使用 **Tone.js** 庫。
- 管理 Tone.Player 實例 (用於預加載的音效文件) 和合成器 (Synth, NoiseSynth)。
- 提供播放單個預載音效 (`playSingleSoundEffect`)、合成音效 (`playSynthSound`) 和合成音效序列 (`playSynthSequence`, `playSoundEffectFromCommand`) 的方法。
- 處理 AudioContext 解鎖 (`unlockAudioContext`)。
- 設置全局音量 (`setGlobalVolume`)。
- **上下文**: 主要由 `useSoundEffects` Hook 調用，用於播放非歌曲類的、較短的音效，例如 UI 反饋、合成測試等。

### 4.3 `useSoundEffects` Hook

位置: `prototype/frontend/src/hooks/useSoundEffects.ts`

功能:
- 作為 `SoundEffectService` 的 React Hook 封裝。
- 提供服務狀態 (`isReady`, `isLoading`, `globalVolume`) 和操作方法。
- **上下文**: 供 `SoundEffectPanel` 等 UI 組件使用，方便調用 Tone.js 相關的音效功能。

### 4.4 `FreesoundService` & `useFreesoundAPI` Hook

位置: `prototype/frontend/src/services/FreesoundService.ts`, `prototype/frontend/src/hooks/useFreesoundAPI.ts`

功能:
- 封裝與 Freesound API 的交互 (通過後端代理)。
- 提供搜索 (`search`)、加載更多 (`loadMore`)、獲取預覽 URL (`getPreviewUrl`)、緩存音效 (`cacheSound`) 等功能。
- Hook (`useFreesoundAPI`) 管理搜索狀態、結果和緩存。
- **上下文**: 主要用於 `SoundEffectPanel` 的 Freesound 標籤頁。

### 4.5 `AudioService` (TTS 播放)

位置: `prototype/frontend/src/services/AudioService.ts`

功能:
- 負責接收後端推送的 TTS 語音數據並播放。
- 可能使用 `HTMLAudioElement` 或直接使用 Web Audio API。
- **上下文**: 由 `WebSocketService` 觸發，獨立於 `SoundEffectPanel` 中的歌曲和音效播放，是**潛在衝突源**。

### 4.6 `SoundEffectPanel` 組件

位置: `prototype/frontend/src/components/SoundEffectPanel.tsx`

功能:
- 提供集中的 UI 界面，包含多個標籤頁 (歌曲、合成音效、Freesound)。
- **實例化 `AudioPlayerService`** 用於歌曲播放。
- **使用 `useSoundEffects` Hook** 調用 Tone.js 音效。
- **使用 `useFreesoundAPI` Hook** 進行 Freesound 操作。
- 包含歌曲播放列表 (`sampleSongs`) 和動畫線索 (`AnimationCue`) 的定義。
- **實現 `startAnimationLoop`** 邏輯，根據 `AudioPlayerService` 的時間同步動畫。
- **狀態**: 目前組件內部狀態和邏輯較多，職責不夠清晰，**是重構的主要目標之一**。

### 4.7 `useStore` (Zustand 狀態管理)

位置: `prototype/frontend/src/store/useStore.ts`

功能:
- 存儲與音頻/動畫相關的全局狀態，例如：
    - `isSpeaking`: 標識角色是否正在說話或唱歌。
    - `currentAnimation`: 當前應播放的身體動畫名稱。
    - `setAudioLipsyncTarget`: 用於觸發口型動畫。
- **上下文**: 被多個服務和組件讀取/修改，用於跨模塊通信和狀態同步。

### 4.8 `AnimationCue` 接口

位置: (可能定義在 `types` 文件夾或直接在 `SoundEffectPanel.tsx` 中，需確認)

定義: `interface AnimationCue { time: number; type: 'action' | 'emotion' | 'viseme'; value: string; }`

功能:
- 標準化聲音事件與動畫同步的數據結構。
- 將時間戳 (`time`) 映射到具體的動畫類型 (`type`) 和名稱/值 (`value`)。
- **上下文**: 目前主要用於 `SoundEffectPanel` 中的歌曲數據，驅動 `startAnimationLoop` 中的動畫觸發。

### 4.9 `HeadService` (表情控制)

位置: `prototype/frontend/src/services/HeadService.ts`

功能:
- 封裝與 3D 頭像/模型表情控制相關的 API。
- 暴露 `applyPresetExpression(presetName)` 等方法，用於快速套用預設表情。
- **上下文**: 在 `SoundEffectPanel` 的 `startAnimationLoop` 中被呼叫，根據 `AnimationCue` 的 `emotion` 觸發對應表情。

### 4.10 `WebSocketService` (前端 WebSocket)

位置: `prototype/frontend/src/services/WebSocketService.ts`

功能:
- 建立並維護與後端的 WebSocket 連線 (singleton)。
- 接收各類型訊息，其中音效相關有:
    - `audio-effect`: 交由 `SoundEffectService` 處理 Tone.js 合成或預載音效。
    - `tts-audio`: 交由 `AudioService` 播放 TTS 語音並驅動口型動畫。
- 發佈狀態或錯誤至全域 store (如需)。
- **上下文**: 是前端與後端音頻/語音事件的唯一橋樑，日後也可作為時間軸協調器的事件來源。

## 5. 音效系統當前問題與限制 (更新)

1. **音頻衝突**: 後端推送的 TTS 語音 (`AudioService`) 與前端播放的歌曲 (`AudioPlayerService`) 缺乏協調，會導致聲音重疊或打斷。
2. **`SoundEffectPanel` 臃腫**: 組件功能過多，狀態管理複雜，難以維護和擴展。
3. **職責分散**: 音頻播放邏輯分散在 `AudioPlayerService` (歌曲) 和 `SoundEffectService` (合成音效) 中，缺乏統一管理。
4. **動畫同步耦合**: 動畫同步邏輯 (`startAnimationLoop`) 目前實現在 `SoundEffectPanel` 中，與 UI 耦合過緊。
5. **缺乏統一時間軸**: 沒有中心化的時間軸協調器來管理所有音頻事件 (TTS, 歌曲, 音效) 及其關聯的動畫。

## 6. 擴充方向與建議

### 6.1 架構改進

1. **直接與對話流程整合**：在對話節點處理過程中，可以直接嵌入音效判斷與生成，而不是作為後處理步驟。
2. **即時音效反饋**：為對話的不同階段添加專屬音效（開始輸入、思考中、回覆開始、回覆完成等）。
3. **音效事件系統**：建立基於事件的音效觸發機制，讓系統中的各個環節都能觸發相應音效。

### 6.2 音效內容擴充

1. **更多音效模式**：增加更多特色音效，如「神秘」、「戲劇化」、「懸疑」等。
2. **隨機變化**：為同一音效模式添加多種變體，避免重複聽感。
3. **音效組合**：允許多種音效模式組合，創造更豐富的聽覺體驗。
4. **背景音樂與環境音**：加強背景音樂系統，根據對話內容動態調整背景音樂氛圍。

### 6.3 用戶互動增強

1. **用戶發言觸發**：分析用戶輸入文本，為其添加相應音效（例如用戶問問題時播放疑問音效）。
2. **關鍵詞觸發**：定義特殊關鍵詞，當出現時播放特定音效（如提到「火箭」時播放發射音效）。
3. **音效個性化**：允許用戶選擇或自定義音效風格。

### 6.4 性能與穩定性

1. **音效優先級系統**：當需要同時播放多個音效時，基於優先級決定播放順序。
2. **降級策略**：在設備性能不足或網絡延遲高的情況下，自動簡化音效複雜度。
3. **緩存機制**：常用音效可以在前端緩存，減少網絡傳輸。

## 7. 實施方案

### 7.1 短期改進計劃

1. **修復音效觸發**：確保 WebSocket 正確傳輸音效命令，並在前端正確處理。
2. **增加觸發點**：在對話流程的多個關鍵點添加音效觸發。
3. **豐富音效庫**：擴展現有音效模式，增加變體和組合。
4. **日誌優化**：完善音效系統的日誌，便於排查問題。

### 7.2 中長期改進計劃

1. **音效引擎重構**：考慮採用更先進的音效引擎或庫。
2. **AI驅動音效**：使用機器學習模型分析對話內容和情緒，自動生成最合適的音效。
3. **用戶反饋整合**：收集用戶對音效的反饋，持續優化音效體驗。
4. **跨平台適配**：確保音效系統在不同設備和瀏覽器上表現一致。

## 8. 開發者指南

### 8.1 添加新歌曲與動畫

1. 將歌曲文件放入 `public/audio/songs/`。
2. 在 `SoundEffectPanel.tsx` 的 `sampleSongs` 陣列中添加新的歌曲對象，包含 `id`, `name`, `url`。
3. (可選) 為歌曲添加 `animationCues` 陣列，定義時間戳、類型 (`action`/`emotion`) 和動畫名稱/表情預設名稱。
4. 確保 `action` 對應的動畫名稱存在於 `animations.json` 或相關配置中。
5. 確保 `emotion` 對應的預設名稱存在於 `HeadService` 的預設表情中。

### 8.2 測試歌曲動畫同步

1. 打開音效控制面板。
2. 切換到「歌曲庫」標籤。
3. 播放帶有 `animationCues` 的歌曲。
4. 觀察角色是否在對應時間點執行了指定的動作和表情。
5. 檢查瀏覽器控制台 `startAnimationLoop` 中的日誌輸出。

### 8.3 測試合成音效

1. 打開音效控制面板。
2. 切換到「合成音效」標籤。
3. 點擊預設按鈕播放單個合成音效。
4. 在 JSON 輸入框中粘貼音效序列指令 (參考範例)。
5. 點擊「執行合成序列」按鈕，驗證音效是否按時序播放。

### 8.4 測試 Freesound

1. 打開音效控制面板。
2. 切換到「Freesound」標籤。
3. 輸入關鍵詞搜索或點擊標籤。
4. 點擊「預覽」按鈕播放音效。
5. 點擊「收藏」按鈕。
6. (如果實現) 在「我的收藏」中查看並播放已收藏音效。

### 8.5 常見問題排查 (更新)

1. **歌曲/音效無法播放**: 檢查 `isReady` 狀態 (針對 Tone.js 音效)，確認 AudioContext 是否已解鎖 (通常需要用戶互動)，檢查文件路徑是否正確，查看控制台錯誤。
2. **動畫未觸發**: 確認歌曲數據中 `animationCues` 是否正確定義，時間戳是否準確，`action`/`emotion` 的 `value` 是否與配置匹配，檢查 `startAnimationLoop` 是否正常運行，查看控制台錯誤。
3. **TTS 與歌曲衝突**: 這是已知問題，需要實現協調機制 (見重構 TODO)。

## 9. 結論

音效系統為太空中心對話體驗增添了聽覺維度，使互動更加豐富和引人入勝。**當前的實現結合了 `HTMLAudioElement` (歌曲) 和 Tone.js (合成音效)，並初步實現了歌曲與動畫的同步。然而，系統存在音頻衝突、組件臃腫、職責分散等問題，需要根據重構計畫進行迭代和優化，特別是引入統一的 `AudioTimelineCoordinator` 和解決播放衝突。** 通過持續改進和擴展，我們可以逐步實現類似「直播網紅」和「綜藝樂隊」的音效體驗，為用戶創造更加沉浸式的互動環境。
