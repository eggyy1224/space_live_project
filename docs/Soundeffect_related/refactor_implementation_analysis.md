# 音效系統實現現況分析

本文件分析目前 space_live_project 的音效系統實現狀況，對照重構計劃，評估已完成部分與後續工作。

## 一、現有音效系統架構

目前的音效系統主要由以下組件組成：

### 1. SoundEffectService（音效服務）

位於 `prototype/frontend/src/services/SoundEffectService.ts`，這是一個單例服務，主要功能：

- 管理 Tone.js 相關資源，包括音效播放器和全局音量控制
- 加載預設音效資源（從 soundEffectsConfig.ts 定義的靜態資源）
- 提供單一音效播放（`playSingleSoundEffect`）
- 支援 Tone.js 合成音效生成（`playSynthSound`）
- 提供多音效序列播放功能（`playSynthSequence` 和 `playSoundEffectFromCommand`）
- 控制全局音量和音效停止功能

這個服務實現了基本音效播放，但**缺乏**時間軸協調機制和資源分級管理。

### 2. AudioService（音頻服務）

位於 `prototype/frontend/src/services/AudioService.ts`，主要負責：

- 處理語音輸入（麥克風錄音）
- TTS 音頻播放和分析
- 與模型動畫系統的整合（口型同步）

此服務主要處理與 TTS 和語音輸入相關的功能，但與音效系統是分離的，沒有統一時間軸協調。

### 3. AudioPlayerService（通用音頻播放器）

位於 `prototype/frontend/src/services/audioPlayer.ts`，提供：

- 標準化的音頻播放接口
- 事件處理機制（播放、暫停、結束等）
- 音頻分析功能

這是一個通用的音頻處理工具，但並未與音效系統緊密整合。

### 4. FreesoundService（Freesound API 服務）

位於 `prototype/frontend/src/services/FreesoundService.ts`，功能包括：

- 搜索 Freesound 音效資源
- 獲取音效詳情和預覽
- 本地緩存機制（僅基本實現）

已經實現 Freesound API 整合的基礎，但缺乏分級快取策略和深度整合。

### 5. 前端 Hook 和組件

- `useSoundEffects.ts`：封裝音效服務的 React Hook
- `useFreesoundAPI.ts`：封裝 Freesound API 的 React Hook
- `SoundEffectPanel.tsx`：音效控制面板 UI 組件

這些前端組件提供了基本的使用介面，但缺少時間軸視覺化和高級功能。

## 二、對照重構計劃的差距

### 已實現部分

1. **基本音效播放功能**：
   - 使用 Tone.js 播放預定義音效和合成音效
   - 支援簡單的音效序列播放
   - 基本的音效參數控制（音量、音色等）

2. **Freesound API 基礎整合**：
   - 搜索和獲取 Freesound 音效資源
   - 音效預覽和簡單緩存
   - UI 介面整合

3. **TTS 與麥克風輸入處理**：
   - 基本的 TTS 音頻處理
   - 口型動畫簡單同步

### 未實現或需改進部分

1. **核心架構**：
   - **缺少 AudioTimelineCoordinator**：缺乏統一的時間軸協調機制
   - **未定義 AudioTimeline JSON**：沒有標準化的時間軸描述格式
   - **模組未明確拆分**：SoundEffectManager 同時處理資源和播放邏輯

2. **資源管理**：
   - **無 Tier 分級系統**：未實現 Tier-0/1/2 的資源分級
   - **快取策略不完善**：僅有基本的本地存儲，無完整快取生命週期管理
   - **離線支援薄弱**：缺乏系統性的離線資源管理

3. **播放控制**：
   - **缺乏衝突處理**：無法處理同時播放多個音效時的優先級和衝突
   - **無 ducking 功能**：缺乏在語音播放時自動降低背景音量的功能
   - **缺少時間精確控制**：播放時序控制粗糙，無法實現精確時間軸排程

4. **UI 整合**：
   - **無時間軸可視化**：缺乏直觀的時間軸編輯和預覽介面
   - **缺乏高級控制功能**：沒有完整的音效組合和編輯工具

5. **前後端整合**：
   - **前後端界限模糊**：職責分工不明確
   - **指令格式不統一**：缺乏標準化的指令結構

## 三、下一步實施建議

根據重構計劃和現有進展，建議按以下順序推進：

### 第一階段（優先）

1. **定義 AudioTimeline JSON 格式**
   - 設計詳細的 JSON Schema，包含時間、類型、資源、參數等字段
   - 建立範例集，覆蓋各種音效場景
   - 實現基本的驗證器

2. **實現 AudioTimelineCoordinator 基本框架**
   - 建立協調器類結構，明確責任範圍
   - 實現時間軸解析和事件排程邏輯
   - 添加基本事件發佈/訂閱機制

3. **重構 SoundEffectManager**
   - 剔除排程邏輯，聚焦於資源管理
   - 規範化接口，與協調器配合
   - 增加狀態監控機制

### 第二階段

1. **實現資源分級系統**
   - 建立 Tier-0/1/2 分類標準和配置結構
   - 開發基於 IndexedDB 的資源存儲
   - 實現分級載入和卸載策略

2. **開發 Combo 音效系統**
   - 定義組合音效的數據結構
   - 實現連續播放和時間控制
   - 建立 Combo 編輯和測試工具

3. **建立 UI 工具**
   - 開發時間軸可視化和編輯組件
   - 實現音效預覽和測試功能
   - 整合資源瀏覽和管理功能

### 第三階段

1. **前後端整合**
   - 更新 WebSocket 消息格式，支援時間軸事件
   - 實現後端 API 支援 AudioTimeline 格式
   - 建立前端狀態報告機制

2. **實現 TTS 和音效的統一管線**
   - 重構語音處理流程，整合至時間軸系統
   - 實現口型和表情時間點關聯機制
   - 添加自動 ducking 功能

3. **效能優化和測試**
   - 優化音頻資源載入和釋放
   - 實現進階記憶體管理
   - 建立全面的測試套件

## 總結

目前的實現已經提供了基本的音效播放功能和 Freesound 資源整合，但距離完整的重構目標仍有顯著差距。關鍵挑戰在於建立統一的時間軸協調機制、實現資源分級管理，以及前後端職責明確劃分。

建議優先完成 AudioTimeline JSON 格式定義和 AudioTimelineCoordinator 框架實現，作為後續工作的基礎。同時，重構現有 SoundEffectManager 以符合新架構的職責劃分，為後續功能擴展提供清晰的基礎結構。

在早期階段應採用漸進式方法，確保新舊系統可以並行運作，避免影響現有功能。可以考慮先實現一個簡單的時間軸播放示例，驗證基本概念，然後再逐步擴展到完整功能。
