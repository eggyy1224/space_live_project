- **表情/頭部事件**：角色表情目前主要來源有兩種：(1) 聲音驅動的口型（AudioService自動更新嘴巴張合）；(2) 可能由後端指令直接設定的表情。例如，如果後端分析對話內容希望角色在說某句時帶有特定表情，理論上可透過 WebSocket 發送一條如 `"expression": "happy"` 的消息或連續的 morph_update 數據流。然而在本分支，`morph_update` 被標註為**移除**（改用狀態管理），且沒有看到明確的 `"expression"` 消息類型處理器。因此推測目前表情（除嘴型外）大多由前端 UI 手動控制（如控制面板選擇預設表情），或未完全實作。HeadService 已經有 `updateMorphTargetInfluence(name, value)` 等接口，可以配合 UI 或其他模組即時改變表情 Morph 值。缺少的是一個機制在**正確的時間**觸發這些改變，使其與語音內容或情緒同步。
- **動作/動畫事件**：目前肢體動畫的切換大多是**離散的**，由使用者或預設行為觸發。例如使用者點擊「揮手」按鈕，則調用 `BodyService.selectAnimation('wave')` 導致模型播放揮手動畫。代碼中也有處理 `"animation_update"` 高頻消息的架構，暗示後端可能連續發送動畫參數（如骨骼的運動軌跡）。然而實際應用上，常見做法是透過單次指令啟動一段預定的動畫（如點頭、笑等）。目前沒有看到專門處理某個**時刻**觸發動畫的邏輯，多為直接立即切換 `currentAnimation` 狀態。也就是說，如果要讓角色在某句話的**特定時間點**開始某動作，目前需靠手動計時觸發，系統本身沒有事件排程去對齊語音和動畫。

**總結**：現有系統能透過各服務分別控制音效、語音、表情和動作，但它們的**觸發時序彼此獨立**。例如語音開始播放時，表情可能尚未切換到合適的情緒，或某背景音效可能與語音重疊不協調。缺乏一個**中央排程**來統籌「在何時做何事」。目前只有音效服務針對自身的多音效情境實現了延時隊列播放 ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=%2F%2F%20%E8%A8%88%E7%AE%97%E6%92%AD%E6%94%BE%E6%99%82%E9%96%93%20)) ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=%2F%2F%20%E5%AE%89%E6%8E%92%E5%9C%A8%E6%8C%87%E5%AE%9A%E6%99%82%E9%96%93%E6%92%AD%E6%94%BE))；而表情和動作沒有類似的機制。這導致我們難以實現複雜的時序效果，例如「角色在2秒後開始微笑，3秒後揮手，同時背景音樂淡入」。為了解決這個問題，我們需要引入時間軸協調模組來統一排程。

## 3. 前端時間軸模組設計（TimelineCoordinator）
為統一管理上述事件，我們設計一個**前端時間軸模組**，暫稱 **`TimelineCoordinator`**，搭配資料結構 **`TimelineEvent`**，作為集中排程和觸發的核心：

- **TimelineEvent 結構**：每個時間軸事件包含：`time`（觸發時間，相對於時間軸開始的毫秒或秒）、`type`（事件類型，例如 `"voice"`, `"sfx"`, `"expression"`, `"action"` 等）、以及該事件類型專屬的 `payload`（例如音效名稱/合成參數、語音音頻資料或URL、表情名稱或數值、動作名稱等）。可以擴充更多欄位如持續時間（duration）供某些事件使用（如一段背景音樂的長度）。
- **TimelineCoordinator 類別**：負責保存一系列 TimelineEvent（可存於一個列表並按時間排序）以及**播放頭（playhead）**狀態。主要職責包括：
  - **排程事件**：提供方法將一組事件加入時間軸並排序。例如 `TimelineCoordinator.scheduleEvents(events: TimelineEvent[])`。在加入時就根據 `time` 排序，或在播放前排序確保按時間先後執行。
  - **播放控制**：提供 `start()`, `pause()`, `resume()`, `stop()` 等控制時間軸的方法。  
    - `start()`：將播放頭歸零並開始按照事件時間推進。可以透過 `requestAnimationFrame` 或 `setInterval` 週期性檢查播放頭當前時間，或直接計算各事件延遲設定定時器。實現上可採用**定時器排程**：例如對每個事件計算相對於現在的觸發延遲，用 `setTimeout` 在延遲後執行事件。為保險起見，對於大量事件或長時序也可採用每幀遞增時間方式（requestAnimationFrame 每帧增加 delta，檢查是否超過某事件時間）。
    - `pause()`：暫停時間軸推進，記錄當前播放頭時間並清除尚未觸發的定時器。  
    - `resume()`：從暫停處繼續，重新排程剩餘事件（需將每個尚未執行的事件的觸發時間減去已經過的pause時間差）。
    - `stop()`：停止播放並重置狀態，清除所有未執行事件，播放頭回到初始。
  - **事件觸發**：當時間軸到達某事件的指定時間（或透過定時器到了），TimelineCoordinator執行對應的處理邏輯。這裡我們將不同 `type` 的事件對應到調用不同的前端服務或狀態更新：
    - **Voice**（語音）事件：透過 AudioService/Audio 元件播放 TTS 音頻。例如payload包含後端返回的語音URL或 Blob，觸發時AudioService載入該音源並播放。同時將 AudioService的`isSpeaking`設為true並啟動嘴型分析。TimelineCoordinator也可以監聽該音頻的結束事件來知道語音播放總時長，用於確定時間軸結束點。
    - **SFX**（音效）事件：調用 `SoundEffectService.playSingleSoundEffect(name)` 或 `playSoundEffectFromCommand` 播放指定的音效。由於SoundEffectService本身也可接受延遲參數，但為了一致性，建議TimelineCoordinator不直接利用其內部延遲機制，而是在事件時間點再調用播放（確保所有不同類型事件統一由Timeline掌控時序）。音效事件也可包含特殊payload，例如帶有fade-in/out參數、音量等，必要時在觸發時調用 SoundEffectService 前先設置 globalVolume 或音量參數 ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=public%20setGlobalVolume%28volume%3A%20number%29%3A%20void%20)) ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=%2F%2F%20%E8%A8%AD%E7%BD%AE%E5%85%A8%E5%B1%80%E9%9F%B3%E9%87%8F))。
    - **Expression**（表情）事件：在觸發時改變角色面部表情。可設計兩種形式的payload：其一是預定義的表情狀態（如 `"happy"`, `"sad"`），TimelineCoordinator 會呼叫 HeadService 提供的新方法如 `applyExpression(presetName)`。該方法內部對應若干 morph target 值（可在 `shared/config` 中定義表情對應的 morphTargets）。另一種是直接給出某些 morph target 的目標值，TimelineCoordinator則逐個調用 `HeadService.updateMorphTargetInfluence(name, value)` 更新 ([space_live_project/prototype/frontend/src/services/HeadService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/HeadService.ts#:~:text=public%20updateMorphTargetInfluence,void))。第一種適合瞬時切換整體表情，第二種可用於連續漸變（例如逐漸揚起嘴角，可以在時間軸上放多個細微變化事件形成漸變效果）。為了避免表情突變，也可以考慮在 TimelineCoordinator 中實現**插值**：例如若需要在1秒內從哭臉變成笑臉，可以產生多個中間事件（或每幀更新）漸進修改 morph 值。不過首版可先採用離散事件切換表情狀態。
    - **Action**（動作）事件：在觸發時令角色播放某段動畫。TimelineCoordinator可以呼叫 `BodyService.selectAnimation(name)` 切換當前動畫 ([space_live_project/prototype/frontend/src/services/BodyService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/BodyService.ts#:~:text=%2F%2F%20%E9%81%B8%E6%93%87%E7%95%B6%E5%89%8D%E5%8B%95%E7%95%AB))。由於3D模型動畫通常有自己持續時間，例如揮手可能持續2秒，此處 TimelineEvent 的 payload 可包含一個長度，用於在 TimelineInspector 中展示。但實際播放上，一旦切換 `currentAnimation`，Three.js 會自行播放完整動畫。我們需要考慮如果後續還有動畫事件，中途是否打斷前一個動畫。一般來說，一個timeline應避免重疊衝突的動畫事件，可以通過設計不重疊時間或在下一事件開始前結束上一動畫來處理。如果真的需要中斷，可在下一事件執行前再調用一次 selectAnimation（Three.js會立即切換）。TimelineCoordinator本身也可在適當時刻重置 `currentAnimation` 為空或預設姿勢，以結束某些循環動畫。
    - **其他**：易擴充新的事件類型，例如 **表情語音同步**（如後端提供逐字的嘴型viseme資料，可以當作特殊的 high-frequency expression 事件，不過當前系統用音量分析取代了viseme）、**攝影機/視角** 事件（切換鏡頭）等，都可以納入 TimelineEvent 機制。
  - **播放頭推進與同步**：TimelineCoordinator需要追蹤當前播放時間（播放頭位置）。在 `start()` 時記錄開始的 `performance.now()` 作為基準，或使用累加計時方式。在每次`requestAnimationFrame`回調中計算已過時間進而推進播放頭，或藉由事件定時器推進。為了讓外部可視化（如 TimelineInspector）獲取播放頭位置，Coordinator可以透過回調或發送一個特殊的`"tick"`事件更新。目前可簡化處理：例如每幀將播放頭時間更新到一個 Zustand 狀態或Ref中。這樣 `<TimelineInspector>` 元件可以訂閱該狀態進行顯示。播放頭也用於在 `pause()` 時保存進度，以及在實現**拖動定位**（seek）時輔助計算。
  - **生命週期與作用域**：TimelineCoordinator 可以設計為單例（app中同時間只需一條全局時間軸控制主角的行為），也可以每次AI回覆時實例化一個短生命的時間軸（管理該句對話期間的事件）。由於我們需要在整個應用中調度統一的角色，採用單例模式較直接：全局僅有一個 TimelineCoordinator 實例，其事件列表在每次新的對話輸出時重置。這個實例可掛載在 React Context 或 Zustand store 中以便各處存取。單例的好處是 `<TimelineInspector>` 等調試工具可方便地取得當前的 timeline 狀態。

總之，TimelineCoordinator 提供了一種**集中式的時間軸**，將原本獨立的事件串在一起按時間順序執行。我們可以把它看作前端的「導演」，在適當的時刻叫演員（語音、音效、表情、動畫）各就各位地表演。接下來討論如何將此模組融入現有系統並與各服務交互。

## 4. 實作規劃與模組整合建議
實作將分為幾個步驟，盡可能重用現有服務，並做好模組分層，確保 TimelineCoordinator 無需關心底層實現細節。以下是具體可行的步驟與涉及的檔案修改：

1. **建立時間軸協調模組**：在前端 src 目錄新建 `services/TimelineService.ts`（或 TimelineCoordinator.ts）。定義 `interface TimelineEvent`（欄位如 time, type, payload）和 `class TimelineCoordinator`。實作上述方法：`scheduleEvents()`（或內部直接在 start 時接受 events 列表參數）、`start()/pause()/resume()/stop()` 等。此檔案為核心邏輯實現檔。範例架構：
   ```ts
   // src/services/TimelineService.ts
   export type TimelineEventType = 'voice' | 'sfx' | 'expression' | 'action' | ...;
   export interface TimelineEvent { time: number; type: TimelineEventType; payload: any; }
   export class TimelineCoordinator {
       private events: TimelineEvent[] = [];
       private startTime = 0;
       private playhead = 0;
       private timerIds: number[] = [];  // 用於記錄已設置的timeout編號
       // ... 實現單例 (例如 static instance) 或在 index.ts 匯出實例
       scheduleEvents(events: TimelineEvent[]) { ... }  // 保存事件並排序
       start(events?: TimelineEvent[]) { ... }          // 可選地傳入新事件列表
       pause() { ... }
       resume() { ... }
       stop() { ... }
       private triggerEvent(evt: TimelineEvent) { ... } // 核心: 根據evt.type呼叫不同服務
   }
   ```
   為了讓其他部分訪問，我們可在 `services/index.ts` 將 TimelineCoordinator 實例導出，例如：
   ```ts
   // services/index.ts
   export const timeline = TimelineCoordinator.getInstance();
   ```
   這樣 React 組件或ChatService都可以匯入 `timeline` 使用。

2. **設計 TimelineEvent 與服務接口對接**：實現在 `triggerEvent()` 中的邏輯。可使用 switch 或對象映射：
   - `case 'voice'`: 假設 payload 包含 `{ url: string }`（語音音檔URL）或 `{ audioBlob: Blob }`，則觸發時：
     - 使用 AudioService 播放該音頻。可能需要在 AudioService 中新增方法如 `playAudioFromUrl(url: string)`。由於 AudioService 已有 `playbackAudio: HTMLAudioElement`，我們可直接設置 `playbackAudio.src = url; playbackAudio.play()`。為保持狀態一致，這方法內應該設置 `useStore.getState().setIsSpeaking(true)` 且在音頻 ended 時設 false。
     - 啟動 AudioService 的 playback analyser。如果 AudioService 的 analyser 是在 `playAudioFromUrl` 裡已經啟動，那TimelineCoordinator無須理會。否則可在 AudioService中檢查 audio start 時啟動 analysePlaybackFrame loop。
     - 如果 audio 播放結束需要通知 TimelineCoordinator（例如自動停止 timeline或執行結尾事件），可在 AudioService的 ended事件裡調用 TimelineCoordinator.stop() 或發出一個特定事件類型（例如 `'voice_end'`）讓 TimelineCoordinator 捕捉處理。不過通常我們會根據已知的音頻時長來安排timeline長度，所以也可不依賴事件。
   - `case 'sfx'`: payload 可能是 `{ name: 'gun_shot', options?: { volume: 0.8 } }` 或類似。TimelineCoordinator調用 `SoundEffectService.playSingleSoundEffect(name, volume)` 即可。由於 SoundEffectService 本身有 isReady 判斷，需確保在整個應用初始化時已調用過 `loadSoundEffects` 載入所需音效。如果某音效尚未載入，這次播放會失敗並記錄警告 ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=if%20%28%21this.players%5Bname%5D%29%20)) ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=if%20%28%21this.players%5Bname%5D%29%20))。我們可以在接收到後端劇本前預先載入常用音效，或在 TimelineEvent 加入前檢查 SoundEffectService.isReady，必要時先調用 loadSoundEffects 再加入 timeline。若有**多個**音效須同時或連續播放，也可為每一個建立單獨TimelineEvent；SoundEffectService 內部其實也支持我們給多個事件時不用timeline逐個呼叫，而以 `playSoundEffectFromCommand` 一次性排程 ([space_live_project/prototype/frontend/src/services/WebSocketService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/WebSocketService.ts#:~:text=%2F%2F%20%E6%92%AD%E6%94%BE%E9%A0%90%E8%A8%AD%E9%9F%B3%E6%95%88%E5%BA%8F%E5%88%97))，但為了一致性和易於視覺化，我們建議還是將每個音效作為獨立TimelineEvent。
   - `case 'expression'`: payload 可以是字串或對象。設計兩種處理：
       1. **表情預設**：如果 payload 是 `{ preset: 'angry' }` 等預設名稱，則我們要將角色切換到對應表情。例如可在 `HeadService` 新增 `setEmotion(emotion: string)` 方法，在內部依據預設定義呼叫若干次 `updateMorphTargetInfluence` 更新一組 morph 值。同時也更新一個狀態值如 `currentEmotion` 以備UI或其他邏輯使用。表情預設定義可放在例如 `config/expressions.ts`，例如：`angry = { "eyeWide": 0, "browDown": 1, "mouthOpen": 0.2 }` 等。
       2. **直接Morph值**：如果 payload 是 `{ morph: 'jawOpen', value: 0.5 }` 或 `{ morphs: { jawOpen: 0.5, smile: 1.0 } }`，則TimelineCoordinator逐一呼叫 `HeadService.updateMorphTargetInfluence(name, value)` 或透過 store action 更新 ([space_live_project/prototype/frontend/src/services/HeadService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/HeadService.ts#:~:text=public%20updateMorphTargetInfluence,void))。這適合精細控制單個表情部位，如張嘴程度等。需要注意，如果持續更新高頻（如每幀嘴型），應透過 WebSocketService 的高頻消息機制或AudioService，不走Timeline，以免衝突。
       無論何種方式，表情的改變通常是瞬時的（但效果會持續直到下一次改變）。因此 TimelineEvent 可只在更改表情當下觸發一次。如果需要表情在一段時間後復原，可以在未來時間再排一個事件切回預設表情。
   - `case 'action'`: payload 例如 `{ animation: 'wave' }` 或 `{ animation: null }`（null表示恢復Idle）。TimelineCoordinator執行 `BodyService.selectAnimation(payload.animation)` ([space_live_project/prototype/frontend/src/services/BodyService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/BodyService.ts#:~:text=%2F%2F%20%E9%81%B8%E6%93%87%E7%95%B6%E5%89%8D%E5%8B%95%E7%95%AB))。由於 BodyService.selectAnimation 本身即更新全局 `currentAnimation` 狀態，綁定該狀態的 Three.js 組件會自動開始播放動畫。如果需要在動畫結束時做處理，可以依動畫時長預先在 timeline 插入另一事件（比如將 animation 設為 idle），或依靠Three.js的 AnimationMixer 完成事件，但這屬於模型層細節，可後續擴充。簡單起見，我們可以假定動畫自己循環或自停，不影響timeline繼續執行後續事件。
   - 針對**未分類或未知事件**：可以在 triggerEvent 實作預留一個 `'default'` 或 `'*'`分支，直接忽略或發出警告，確保不會因未知類型導致錯誤中斷時間軸。

3. **修改 ChatService 整合 Timeline**：打通從後端回覆到時間軸的流程。在 `ChatService.ts`（或相關處理AI回覆的模組）中，引入 TimelineCoordinator 將AI回覆解析為事件：
   - **取得AI回覆**：假設後端通過 WebSocket 發回的聊天消息類型為 `"chat"` 或 `"response"`，其中包含 AI回答的文字、語音URL、以及可能的動作/表情指示。我們需要在 WebSocketService 或 ChatService 相應 handler 中組裝 TimelineEvents。例：當 ChatService 得到 `answerText` 和 `audioUrl` 時：
     1. 建立語音事件：`{ time: 0, type: 'voice', payload: { url: audioUrl } }` — 讓語音從時間0開始播放。
     2. 如果後端有提供情緒隨時間變化的資料（例如 emotionalTrajectory: [ { t:500, emotion:'happy' }, { t:1500, emotion:'neutral' } ] 表示0.5秒時表情切換微笑，1.5秒時回復中性），則將每個節點轉為 expression事件。例如 `{ time: 500, type: 'expression', payload: { preset: 'happy' } }`, `{ time: 1500, type: 'expression', payload: { preset: 'neutral' } }`。
     3. 如果後端提供了建議的動作（例如 AI回覆內容包含「*（揮手）*」的標記，或額外欄位action:"wave"），我們可以解析出在何時執行。假設策略是讓動作在語音開始時就做，則 time=0；或者在句尾做則 time=整段語音長度減0.5秒等。將其加入事件，例如 `{ time: 0, type: 'action', payload: { animation: 'wave' } }`。
     4. 如果有背景音樂或環境音效需要在此對話段落中播放，也一併加入。例如後端指示在本段開始時播放欢快音樂，可以 `{ time: 0, type: 'sfx', payload: { name: 'bgm_happy', options:{ volume:0.6 } } }`；若需要在結束時淡出音樂，可以在結束時間點再加一個 sfx 事件，payload指示停止或降低音量（SoundEffectService可新增stopSound(name)方法來停止某音效 ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=public%20stopSound%28name%3A%20string%29%3A%20boolean%20)) ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=try%20))）。
   - **啟動時間軸**：完成事件列表組裝後，呼叫 `timeline.start(events)`。TimelineCoordinator 接管後續的定時觸發。此時 ChatService 可以將回覆文字顯示在聊天介面，但不再需要管表情/動作/音效，因為都交由 timeline 執行。
   - **等待/同步**：若需要在該段表演完成後才允許下一次輸入或下一段對話，ChatService 可以透過 TimelineCoordinator 提供的回調（例如傳入 start 的可選回調參數）或檢查 `timeline.isRunning` 狀態來決定何時允許下一步。例如，可以在 timeline 結束（所有事件執行完）時觸發一個 `'timelineEnd'` 事件，ChatService 監聽到後再繼續流程（如自動請求下一句對話等）。這部分可在實作時透過 Promise 或事件總線完成，但要注意避免 blocking UI。

4. **擴充現有服務介面**：為配合 TimelineCoordinator，需要在部分服務中新增方法或調整：
   - **AudioService**：實現 `playAudioFromUrl(url: string): Promise<void>` 或類似功能。具體在 AudioService 中，可以創建或使用已有的 `this.playbackAudio`元素：
     ```ts
     playAudioFromUrl(url: string) {
         if (!this.playbackAudio) {
             this.playbackAudio = new Audio();  // 建立新的 Audio 元素
             this.playbackAudio.onended = () => {
                 useStore.getState().setIsSpeaking(false);
                 // 可以在這裡調用 timeline.onVoiceEnded() 如果需要通知
             };
         }
         this.playbackAudio.src = url;
         useStore.getState().setIsSpeaking(true);
         this.playbackAudio.play();
     }
     ```
     如此，TimelineCoordinator 觸發 voice事件時，只需 `AudioService.getInstance().playAudioFromUrl(payload.url)`。由於 AudioService 原本在錄音用到 audioContext 並行了 analyser，我們需要確保在播放時也適用。可以在 AudioService 中判斷如果已有 `playbackAnalyserNode`就繼續用，沒有就建立。例如利用 `audioContext.createMediaElementSource(this.playbackAudio)` 建立 source node，再connect到 AnalyserNode（如果未連）。這部分細節在AudioService已有所涉及，例如 `playbackSourceNode: MediaElementAudioSourceNode` 和 `playbackAnalyserNode: AnalyserNode` 屬性 ([space_live_project/prototype/frontend/src/services/AudioService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/AudioService.ts#:~:text=private%20analyser%3A%20AnalyserNode%20,null))。實作時可復用它們，不需要每次重建。只要在第一次播放時初始化 `playbackAnalyserNode` 並 connect 即可。這樣 audio 播放時 Analyzer 就會工作，保持口型同步機制正常。
   - **SoundEffectService**：大部分情況下可直接使用現有方法。但我們可以新增一個簡便方法 `play(name, options)` 作為 `playSingleSoundEffect` 和 `playSynthSound` 的封裝，以便 TimelineCoordinator 呼叫時不用區分聲音類型。例如當收到 payload 不含 `synthMode`時，就走`playSingleSoundEffect` ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=public%20playSingleSoundEffect,boolean)) ([space_live_project/prototype/frontend/src/services/SoundEffectService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/SoundEffectService.ts#:~:text=%2F%2F%20%E7%A2%BA%E4%BF%9D%E5%BE%9E%E9%A0%AD%E9%96%8B%E5%A7%8B%E6%92%AD%E6%94%BE))，含 `synthMode` 或特殊類型則走 `playSynthSound`。另外，由於 timeline 控制音效時間，我們**不需**使用 SoundEffectService 的序列播放功能（`playSoundEffectFromCommand`）來處理多音效，同時要防止衝突：建議將 WebSocketService 收到 `"audio-effect"` 時，如果當前有Timeline在運行，改為**將其effects轉換為TimelineEvents插入**，而不是直接呼叫 SoundEffectService 裡自行排程。可以修改 WebSocketService audio-effect 處理處：檢查 `if (timeline.isRunning) {...} else { 原流程 }`。若 timeline 正在執行（例如正在播角色對話），可呼叫 `timeline.insertEvents(events)` 把這些音效納入當前時間軸。否則（如角色沒在說話，只是純音效指令）就用 SoundEffectService 即時播放 ([space_live_project/prototype/frontend/src/services/WebSocketService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/WebSocketService.ts#:~:text=%2F%2F%20%E6%92%AD%E6%94%BE%E9%A0%90%E8%A8%AD%E9%9F%B3%E6%95%88%E5%BA%8F%E5%88%97))。這樣做可以避免時間衝突，確保所有聲音統一經由Timeline調度。
   - **HeadService**：增加高層次表情設定方法，例如 `setEmotion(emotion: string)` 或 `applyExpressionPreset(name: string) -> void`。在內部，可以有一個 `const presets = { happy: {...}, sad: {...} }`，對應若干 morph target 值。調用時遍歷該preset物件，執行 `useStore.getState().updateMorphTarget(key, value)`。或者，如果我們希望在表情切換時有平滑過渡，可以在 HeadService 實作一個簡單的插值：例如每隔50ms改變一點點值持續一段時間完成過渡。不過初期可以直接瞬間設置。**狀態方面**，可以在 headSlice 新增 `currentEmotion` 字段，每次 applyPreset 時也設置此狀態，以便UI顯示或其他邏輯判斷當前情緒。

5. **將 TimelineCoordinator 注入 React 架構**：在 React 應用初始化時（例如 App.tsx），創建 TimelineCoordinator 單例並與各服務初始化順序協調。例如需確保 SoundEffectService.loadSoundEffects 在 timeline 使用前完成，以免 timeline 試圖播放時音效尚未載入（可以在應用啟動後、模型載入前就行）。如果 TimelineCoordinator 單例需要從 Zustand store 知道某些狀態（如 isSpeaking 等），也可在其構造時注入相關 store 實例或服務實例，但最佳做法是讓 TimelineCoordinator **僅通過調用服務接口**來操作，不直接依賴 store，保持鬆耦合。可在 `frontend/src/main.tsx` 把 TimelineCoordinator 實例創建並存入 React Context供需要的組件存取（例如 TimelineInspector）。

6. **測試與驗證**：確保以下流程運作正常：
   - 當 ChatService 接收到簡單的 AI 回覆（只有文字和語音）時，timeline 正確建立語音事件並播放，嘴型同步正常，timeline結束後狀態復原（isSpeaking=false，表情若改變可能保持最後狀態或根據需求復位）。
   - 為回覆添加一個表情事件，驗證在對應時間點角色表情有切換。
   - 為回覆添加一個動作事件，驗證角色在對應時間開始動畫。

   - 測試 WebSocketService 單獨收到 `"audio-effect"` 指令時，能通過 timeline 或直接播放音效（視當時狀況） ([space_live_project/prototype/frontend/src/services/WebSocketService.ts at feature/sound_effcets · eggyy1224/space_live_project · GitHub](https://github.com/eggyy1224/space_live_project/blob/feature/sound_effcets/prototype/frontend/src/services/WebSocketService.ts#:~:text=%2F%2F%20%E6%92%AD%E6%94%BE%E9%A0%90%E8%A8%AD%E9%9F%B3%E6%95%88%E5%BA%8F%E5%88%97))。例如角色不在說話時收到環境音，應立即播放；角色說話時收到，應在timeline中加入或酌情延遲。

## 5. 時間軸視覺化工具（`<TimelineInspector />`）計劃
為方便開發者調試時間軸事件排程，我們建議實作一個React組件 **`<TimelineInspector />`** 作為可視化工具。這個元件在開發模式中掛載，顯示當前 TimelineCoordinator 中的所有事件軌跡以及播放頭位置：

- **界面設計**：`TimelineInspector` 可採用類似音頻/視頻編輯軟件的時間軸視圖。橫軸代表時間線（可標示刻度，如秒），縱向分多條軌道，每條軌道對應一種類型的事件。比如：
  - Voice 軌道：顯示語音事件作為一個橫向條帶，其長度可表示語音持續時間（如果知道的話）。若無法獲取準確時長，也可以用固定長度或僅顯示一個標記點。
  - SFX 軌道：每個音效事件顯示為一個小圖標或短矩形，標註開始時間及名稱。多個音效可以堆疊在此軌道不同位置。
  - Expression 表情軌：將表情事件以不同顏色標記，例如一個笑臉圖標出現在1.0秒處表示角色此時切換笑表情。
  - Action 動作軌：顯示動畫事件名稱及持續時間。可用矩形條表示動畫區間，如果動畫有長度的話。若沒有確切長度資訊，可假設一固定長度表示其存在。
  - 其他軌：可以有 Lipsync 軌（展示嘴型動態，其實這是高頻連續的，不適合用離散圖標，可忽略或用特殊波形表示音量變化）、Emotions 曲線（如果有情緒強度曲線，可以繪制一條隨時間的曲線）。

- **播放頭**：Inspector 繪製一條垂直線作為播放頭位置，隨著 TimelineCoordinator 的進行而水平移動。透過 TimelineCoordinator 提供的當前時間（如存在於其 state），以 requestAnimationFrame 更新該線位置。播放頭可以用不同顏色突出顯示。

- **互動功能**（選配）：開發初期可先做靜態顯示，後期可考慮互動：
  - **拖動播放頭**：允許開發者拖動垂直線改變 timeline 當前時間（實現時間跳躍）。這需要 TimelineCoordinator 提供 `seek(toTime)` 方法，能取消未發生事件並直接跳到未來某時間執行後續（或重放過去事件，此更複雜，一般debug不需要重放，只需要快進）。
  - **點擊事件**：點某個事件圖標，可顯示詳細信息（例如音效名稱、表情值、動畫名稱等），方便確認事件是否正確。
  - **臨時插入/移除事件**：更進階的功能，可允許在Inspector上直接調整事件，用於實驗新的時序。但正式功能中不太需要，因為應由AI或代碼決定timeline，Inspector主要用來**觀察**。

- **實作**：
  - 文件路徑：`src/components/dev/TimelineInspector.tsx`（或放在 components 下新建文件夾 dev）。只有在非生產環境渲染，這可通過環境變數或一個開關實現（例如 `if(import.meta.env.DEV) { <TimelineInspector/> }` 放在App尾部渲染）。
  - 獲取數據：TimelineInspector 可從 TimelineCoordinator 單例取得事件列表和當前時間。一種方式是在 TimelineCoordinator 中加入方法如 `getEvents(): TimelineEvent[]` 和 `getPlayhead(): number`。Inspector通過定時（例如 30fps）或訂閱store方式拿到這些資料。若 TimelineCoordinator 將狀態（如 playhead）存入 Zustand timelineSlice，可直接透過 hook `useStore(state=>state.timelineEvents)` 獲取，自動追蹤更新。為簡化，可在 TimelineCoordinator 每次 start 時將當前 events 列表存入一個全局變數（或其自身靜態屬性），Inspector 每次 render 去讀取。播放頭則每幀讀取 TimelineCoordinator.playhead。
  - 繪圖：可使用純 HTML+CSS。比如，一個容器 div 作為時間軸背景，用 CSS grid 切分多行代表軌道。每個事件渲染為一個絕對定位的子 div，`style.left = (event.time / totalTime * 100)%` 確定水平位置（如果時間軸總長 totalTime 已知，可取語音長度或最後一個事件時間）。如果有持續時間，可同理計算寬度比例。播放頭是一個絕對定位的線條div，高度100%，left按照 currentTime/totalTime 百分比。也可在上方繪製刻度刻線（例如每秒一條細線），輔助判讀。
  - 由於時間軸長度取決於最後一個事件或語音長度，我們可以在 timeline.start 時計算 `totalTime` 並保存於 TimelineCoordinator，以供Inspector使用。假設語音是最長的，那 totalTime 就是語音時長；若音效或動畫超過語音，也應延長 totalTime 以涵蓋全部事件。
  
- **使用**：開發時打開應用，TimelineInspector 將顯示當前 timeline。如果沒有timeline在跑，可顯示「無事件」字樣或空軸。當 ChatService 傳入新事件並 start timeline後，Inspector立即列出事件及移動的播放頭。開發者可以直觀看到各事件的先後和對齊關係。例如，語音條可能長5秒，表情切換點在第2秒處，動作在第0秒到第1秒間。若發現不合理，可直接調整代碼的事件時間或順序再測。

- **舉例**：假設AI回覆：「你好！（開心地揮手）」並合成了3秒語音，TimelineEvents 可能是：
  - `{ time: 0, type: 'voice', payload: { url: '...hello.wav' } }`（語音）
  - `{ time: 0, type: 'action', payload: { animation: 'wave_hand' } }`（揮手動畫）
  - `{ time: 0, type: 'expression', payload: { preset: 'happy' } }`（開心表情）
  - `{ time: 3000, type: 'expression', payload: { preset: 'neutral' } }`（語音結束後恢復中性表情）
  Inspector 將顯示：Voice軌有一段長3秒的條帶，Action軌有一段0~1秒的條帶（假設揮手動畫1秒），Expression軌有一個標記在0秒標示happy，另一個在3秒標示neutral。播放頭從0移到3秒，開頭處三個事件同時開始，1秒時Action結束（如果我們用條帶表示可視察到），3秒處表情切回。這清楚反映了整個排程。

透過 TimelineInspector，我們能方便地調整和優化時間軸模組的行為。例如發現某表情事件時間不對，只要修改對應生成事件的邏輯再觀察。此工具不會隨產品發布，但對開發**深入研究**和除錯非常有價值。
