# 後端回覆速度優化 TODO

## 背景說明
目前系統回應速度緩慢，經分析主要瓶頸來自：
1. 記憶檢索耗時（約2秒）
2. AI模型生成延遲（約1.5秒）
3. 情緒與動畫分析（約2秒以上）
4. 語音合成耗時（約3-5秒）
5. 總處理時間過長（用戶訊息約6.5秒，自言自語約7.2秒）

## 優化目標
* 將總處理時間從7秒縮短至3秒以內
* 減少API調用次數和複雜度
* 提升用戶體驗，減少等待時間

## 記憶系統優化 (高優先級)

- [ ] **限制記憶搜索範圍**
  - 當前問題：每次檢索遍歷完整記憶庫，耗時約2秒
  - 解決方案：只檢索最近N條記憶（例如最近10條），減少搜索空間
  - 具體實施：修改 `retrieve_memory_node` 函數，添加時間或數量限制

- [ ] **優化向量檢索算法**
  - 當前問題：Chroma向量數據庫檢索效率低
  - 解決方案：使用更輕量化的索引方式或切換至FAISS，簡化相似度計算
  - 具體實施：修改 `memory_retriever.py` 中的檢索邏輯

- [ ] **減少記憶依賴**
  - 當前問題：即使是簡單問題也進行完整記憶檢索
  - 解決方案：實現輕量預檢，根據問題複雜度決定是否檢索記憶
  - 具體實施：添加問題預分類邏輯，對簡單問候跳過記憶檢索

## 外部API/模型優化 (高優先級)

- [ ] **替換更輕量級模型**
  - 當前問題：大型模型調用時間長，穩定性相對較低
  - 解決方案：使用Gemini-flash或GPT-3.5-turbo替代大型模型處理部分任務
  - 具體實施：修改 `ai_service.py` 中的模型選擇邏輯

- [ ] **拆分情緒分析與內容生成**
  - 當前問題：單一模型同時處理內容生成和情緒分析
  - 解決方案：使用小型專用模型處理情緒分析和動畫指令
  - 具體實施：將 `analyze_keyframes_node` 邏輯改用小型模型

- [ ] **TTS優化**
  - 當前問題：OpenAI TTS生成時間長（3-5秒）
  - 解決方案：評估其他TTS選項如本地部署的Piper或VITS
  - 具體實施：開發替代TTS插件，在音質和速度間取得平衡

## 異步處理優化 (中優先級)

- [ ] **並行處理增強**
  - 當前問題：情緒分析、TTS等環節串行執行
  - 解決方案：利用asyncio同時處理多任務，如模型生成完成後立即開始TTS和情緒分析
  - 具體實施：重構 `dialogue_graph.py` 中的流程，增加並行節點

- [ ] **分離自言自語處理流程**
  - 當前問題：自言自語和用戶訊息使用相同處理流程
  - 解決方案：為自言自語創建簡化版處理流程，減少記憶依賴
  - 具體實施：在 `websocket.py` 中建立獨立的輕量處理函數

## 系統層面優化 (中優先級)

- [ ] **簡化狀態管理**
  - 當前問題：語音狀態管理複雜且保護緩衝時間過長
  - 解決方案：將 `VOICE_FINISHING_BUFFER` 從0.5秒降至0.2秒，簡化狀態轉換邏輯
  - 具體實施：修改 `websocket.py` 中的 `reset_speaking_after_duration` 函數

- [ ] **減少日誌輸出**
  - 當前問題：過多的日誌記錄降低系統性能
  - 解決方案：降低非關鍵路徑的日誌級別，只保留ERROR和關鍵INFO
  - 具體實施：審查所有日誌語句，將DEBUG和非關鍵INFO改為DEBUG或移除

- [ ] **優化WebSocket訊息處理**
  - 當前問題：訊息處理包含過多保護邏輯
  - 解決方案：簡化訊息處理流程，減少鎖等待時間
  - 具體實施：修改 `process_message_queue` 和相關處理函數
