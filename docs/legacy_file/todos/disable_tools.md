# 工具功能暫時禁用說明

## 背景與原因

系統的工具功能（包括 Wikipedia 搜索、太空新聞搜索、月相查詢等）已被暫時禁用，以提高系統的回應速度。這是因為工具處理流程引入了以下效能瓶頸：

1. **額外的 LLM 調用**：每次用戶輸入都會調用一個小型 LLM (Gemini 1.5 Flash 8B) 來判斷是否有工具使用意圖，這增加了額外的API請求和等待時間。

2. **多重 LLM 調用**：如果檢測到工具意圖，系統還會再次調用 LLM 來解析參數，進一步延長處理時間。

3. **外部 API 調用**：執行工具通常涉及外部 API 請求（如維基百科、太空新聞 API等），這些調用可能導致延遲或超時。

4. **處理開銷**：工具結果的格式化和整合也需要額外的處理時間。

## 改動內容

在 `prototype/backend/services/ai/dialogue_graph.py` 文件中進行了以下更改：

1. 註釋掉所有工具處理相關的節點定義。
2. 移除工具處理路徑，將對話流程從 `filter_memory` 直接連接到 `select_prompt_and_style`。
3. 在 `generate_response` 方法中將 `has_tool_intent` 強制設為 `False`。
4. 清空了 `available_tools` 列表，防止任何工具檢測邏輯嘗試使用工具。

## 效能提升

這些改動預計會顯著提高系統的響應速度，因為：

1. 減少了 API 調用次數（每次對話少至少一次 LLM 調用）。
2. 簡化了處理流程，移除了不必要的檢測和執行邏輯。
3. 避免了因外部 API 而產生的延遲和可能的錯誤處理。

## 如何恢復功能

如果需要恢復工具功能，請按照以下步驟操作：

1. 在 `dialogue_graph.py` 中取消註釋所有與工具處理相關的節點定義。
2. 恢復工具處理路徑，重新設置 `filter_memory` 到 `detect_tool_intent` 的連接。
3. 取消註釋工具分支流程和工具處理流程的定義。
4. 在 `generate_response` 方法中將 `has_tool_intent` 改回 `None`。
5. 將 `available_tools` 恢復為 `self.available_tools`。

## 未來優化建議

如果未來需要恢復並優化工具功能，可考慮以下方向：

1. 使用更輕量的方法來檢測工具意圖，例如關鍵字匹配或規則引擎，而不是每次都調用 LLM。
2. 實現工具結果的緩存機制，避免重複查詢相同內容。
3. 設置更嚴格的超時控制，防止外部API調用過長影響主流程。
4. 考慮對工具功能實施用量限制或使用開關，讓系統在高負載時可以動態禁用工具功能。
