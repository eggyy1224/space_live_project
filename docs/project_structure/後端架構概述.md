# 後端架構概述

本文檔概述虛擬太空人互動藝術裝置專案的後端架構，包含核心技術、目錄結構、API 路由、資料模型與服務協調器等關鍵資訊。

## 核心技術

虛擬太空人後端採用現代化技術棧，主要包含：

- **FastAPI**: 高效能 Python Web 框架，提供非同步處理能力
- **LangChain/LangGraph**: AI 語言模型整合與工作流程框架，用於構建對話系統
- **ChromaDB**: 向量資料庫，用於語義搜尋與記憶系統實現
- **WebSocket**: 即時雙向通訊，實現前後端即時互動
- **Google Gemini**: AI 大型語言模型，提供自然語言理解與生成能力
- **Google Cloud Speech-to-Text**: 語音轉文字服務，處理用戶語音輸入
- **Google Cloud Text-to-Speech**: 文字轉語音服務，生成虛擬太空人語音
- **PostgreSQL/pgvector**: 關聯式資料庫與向量擴展，用於持久化儲存
- **Redis**: 快取與訊息佇列，提升系統效能

這些技術共同構成了虛擬太空人的「大腦」與「記憶」系統，使其能夠理解、回應並記住與用戶的互動。

## API 路由表

後端提供多種 API 端點，用於健康檢查、語音處理與即時通訊：

### 健康檢查 API

| Method | Path | Handler | 說明 |
|--------|------|---------|------|
| GET | /api/health | health.router.get_health | 檢查服務健康狀態 |

### 語音處理 API

| Method | Path | Handler | 說明 |
|--------|------|---------|------|
| POST | /api/speech/text-to-speech | speech.router.text_to_speech | 將文字轉換為語音 |
| POST | /api/speech/speech-to-text | speech.router.speech_to_text | 將語音轉換為文字 |

### WebSocket API

| Path | Handler | 說明 |
|------|---------|------|
| /ws | websocket.websocket_endpoint | WebSocket 連接端點，處理即時對話 |

WebSocket 端點是系統的核心通訊管道，處理前端發送的用戶訊息，並即時回傳虛擬太空人的回應、情緒狀態與動作指令。
為了確保語音播放順序，端點加入了播放握手機制，前端回傳 `playback_ack` 後才傳送下一段音頻。

## 資料模型 / Service & Coordinator

### 資料傳輸物件 (DTOs)

- **requests.py**: 定義 API 請求的資料結構，包含語音轉換、對話請求等
- **responses.py**: 定義 API 回應的資料結構，包含處理結果、錯誤訊息等

### 服務層 (Services)

#### AI 服務

- **ai_service/ai_service.py**: 整合 Google Gemini API，處理自然語言理解與生成
  - 負責解析用戶意圖、生成回應文本、決定情緒反應
  - 與記憶系統協作，提供上下文感知的對話能力

#### 記憶系統

- **memory_system/memory_system.py**: 管理虛擬太空人的記憶系統，包含短期、中期與長期記憶
  - 協調各種記憶組件的運作，提供統一的記憶存取介面
  - 實現記憶的存儲、檢索、更新與遺忘機制

- **memory_system/memory_components/stores/chroma_store.py**: 使用 ChromaDB 實現向量記憶儲存
  - 將對話內容與事件轉換為向量表示，支援語義搜尋
  - 提供高效的相似度查詢，找出與當前情境相關的記憶

- **memory_system/memory_components/retrieval/memory_retriever.py**: 根據上下文檢索相關記憶
  - 分析當前對話情境，構建記憶檢索查詢
  - 從不同記憶存儲中獲取相關記憶，並按相關性排序

- **memory_system/memory_components/processing/summarizer.py**: 記憶摘要與壓縮
  - 將長對話或複雜事件壓縮為簡潔的摘要
  - 定期整合零散記憶，形成更高層次的理解

#### 對話與語音服務

- **dialogue_manager**: 管理對話流程與狀態
  - 追蹤對話歷史與當前狀態
  - 協調 AI 服務與記憶系統的互動

- **murmur_service/murmur_service.py**: 處理虛擬太空人的自言自語功能
  - 在閒置時間生成自發性言論
  - 根據記憶與情境選擇適當的自言自語內容

- **speech_to_text.py**: 整合 Google Cloud Speech-to-Text API
  - 將用戶語音轉換為文字
  - 支援多種語言與口音識別

- **text_to_speech.py**: 整合 Google Cloud Text-to-Speech API
  - 將文字轉換為自然語音
  - 支援情緒表達與語調變化

### AI 服務與 LangGraph

LangGraph 是系統的核心工作流程引擎，用於構建複雜的對話處理流程：

- **ai/dialogue_graph.py**: 定義對話處理的 LangGraph 工作流程
  - 設計對話處理的節點與流程
  - 協調各種處理節點的執行順序與條件

- **ai/graph_nodes/**: 包含各種 LangGraph 節點實現
  - **analysis_nodes.py**: 分析使用者輸入的節點，理解意圖與情緒
  - **input_processing.py**: 處理輸入的節點，清理與標準化文本
  - **llm_interaction.py**: 與 LLM 互動的節點，生成回應與決策
  - **memory_handling.py**: 記憶處理節點，存取與更新記憶
  - **prompting.py**: 提示詞處理節點，構建 LLM 提示
  - **tool_registry.py**: 工具註冊與調用節點，擴展系統能力

## 啟動流程

後端服務可通過以下方式啟動：

1. 使用 run.sh 腳本啟動服務:

```bash
# 使用腳本啟動
./run.sh
```

2. 或直接使用 uvicorn 啟動:

```bash
# 直接使用 uvicorn
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

3. 環境變數配置 (.env 檔案):

```plaintext
# API 金鑰
GOOGLE_API_KEY=your_google_api_key
GEMINI_API_KEY=your_gemini_api_key

# 服務配置
PORT=8000
HOST=0.0.0.0
DEBUG=True

# 資料庫配置
POSTGRES_USER=postgres
POSTGRES_PASSWORD=password
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=spacelive

# 記憶系統配置
MEMORY_PERSIST_DIR=./memory_data
```

## 效能優化與資源管理

系統實施多種效能優化與資源管理策略：

- **WebSocket 資料壓縮**: 減少網路傳輸量，提升即時通訊效能
- **記憶快取機制**: 使用 Redis 快取常用記憶，減少資料庫查詢
- **定期清理過期語音檔案**: 自動管理 debug_audio 目錄，避免磁碟空間耗盡
- **API 使用配額管理**: 控制 Google API 呼叫頻率與數量，避免超出配額限制
- **資源使用監控**: 記錄系統資源使用情況，及時發現潛在問題

這些措施確保系統在保持高質量互動體驗的同時，能夠有效控制資源使用與運營成本。
